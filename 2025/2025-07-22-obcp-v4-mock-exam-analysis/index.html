45 配置项

答案分析：

OB 的配置是最混乱的（合并了 ORACLE 和 MySQL 的配置方法）。这里说的是 参数（parameter），sys租户下的parameter 很多生效范围是整个集群，叫集群参数。sys租户下可以修改用户租户的参数；用户租户下的 parameter 生效范围只有自己的租户。只能改自己的参数。

46 会话变量

答案分析：

用户租户下除了参数（parameter）外还有变量（variable），这个是吸取了 mysql 的变量特性。还分全局变量和会话变量。生效机制和范围跟 MySQL 保持一致。

47 ODP

答案分析：

ODP 就是 OB 集群的反向代理。但是 ODP 集群并不是真的集群，只是一堆 ODP 节点的堆砌，高可用和负载均衡要靠 上面的 负载均衡设计（如F5,A10 或 NGinx、HAProxy、LVS 等）。

48 explain

答案分析：

explain 只能生成执行计划，并不执行 SQL。 这点跟 PG 不一样，没有 explain analyze 用法。

49 合并和统计信息

答案分析：

V4 版本 OB 将每日合并跟 统计信息更新拆开了。统计信息的收集策略越来越丰富多样（自动收集、手动收集、自适应收集、渐进收集…..）。

50 日志流

答案分析：

日志流是 4.x 版本的新东西，不是很好理解。可以参考：OB V4日志流设计分析

总结

这个只是模拟题，但可以看出都是紧扣教程里的概念出的。模拟题地址点下面“查看原文”。

考OBCP 的唯一道路是深刻理解教程中的概念、知识，结合实际OB环境进行练习。背题库没有大用。
