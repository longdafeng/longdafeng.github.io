会话会结束，上下文不死：Codex × PowerContext 实战手记

发表于 2026-09-24 原作者： OceanBase 爱好者 分类于 AI & 应用 阅读次数： 本文字数： 3.3k 阅读时长 ≈ 12 分钟
Codex 与 PowerContext 实战通过账单缓存改造，演示项目记忆的保存、召回、修订与退休，以及 Work Contract、Handoff 和签收机制如何支持跨会话接力。

下午六点，你关掉 Codex，合上电脑，去赴一场约。

晚上十一点回到家，忽然想起白天那个没改完的缓存层。你重新打开 Codex，敲下：“我们下午说到哪了？”

Codex 眨了眨眼（如果它有眼睛的话），干净利落地回答了你的问题——不是客套的“请问有什么可以帮您”，而是：“缓存层用 Redis，键统一加 ledger: 前缀，TTL 三百秒。下一步是先补击穿单测，再灰度百分之十。”

这不是科幻。这是我在本地真实跑通的一次实验，主角是 OceanBase 开源的 PowerContext（0.2.0）。它做的事情用一句话概括：把工作的上下文从“会话的私产”变成“项目的公产”。

欢迎大家关注 OceanBase 社区公众号 “老纪的技术唠嗑局”。在这里，我们会持续为大家更新与 #AI 和 #Data 相关的技术内容~

它解决的那个痛，你一定疼过

用 AI 编程工具的人都经历过这种断裂：上午和 agent 聊得热火朝天，决策做了，坑踩了，代码改了一半；下午换个会话，一切归零。你得像给失忆的同事交接一样，把前因后果重新讲一遍。

更痛的是换人、换工具。这个任务在 Codex 里开了头，想让 Claude Code 收尾？对不起，上下文锁死在第一个工具的对话窗口里，搬家全靠复制粘贴。

PowerContext 的思路是：既然问题出在“上下文寄生于会话”，那就把它抽出来，存进一个跟着项目走的本地服务里。决策、约束、证据、进度，统统落盘；谁来接手——你、同事、另一个 agent——都能从当前状态继续，而不是从考古开始。

安装只有两行，这里不展开（官网教程写得很细）：

下面直接进戏。

开戏：一个不大不小的改造任务

我给自己编了个真实的活儿：给一个记账小服务 ledger 加缓存层。这种任务不大不小，正好会横跨多个会话——上午调研，下午动手，晚上收尾。

三个 Codex 会话，一台本地 PowerContext Server，开演。

第一幕：把“记性”种进项目

上午的会话里，Codex 翻完代码，和我敲定了三件事。我让它存进 PowerContext：

用 PowerContext 存三条项目记忆：

  1. 决策：缓存层用 Redis，键统一加 ledger: 前缀，TTL 默认 300 秒；
  2. 约束：账单接口的缓存不得跨用户共享，键里必须带 user_id；
  3. 下一步：给月度账单汇总接口加缓存，并补一个击穿场景的单测。

返回的东西让我对这个项目的第一印象极好——每条记忆都带一枚引用（citation），精确到条目和版本：

为什么要有 citation？ 因为记忆不是刻舟求剑的石头，而是会生长的活物。后面每一次修订、退休，都凭这枚“身份证”精确操作——改的是哪个版本，一清二楚，杜绝“我以为我改的是这条”的糊涂账。

第二幕：新会话里的“似曾相识”

中午我故意关掉会话，模拟最真实的场景：一个对上午一无所知的全新 Codex 会话。

好戏在这里。Codex 插件带了一个 UserPromptSubmit 钩子，每次提问前，它会悄悄去 Server 捞一圈相关上下文，垫在请求底下。我问：“月度账单接口的缓存怎么加？”返回的 PreparedContext 里，上午三条记忆赫然在列，还带着一段意味深长的前缀：

untrusted_history——不可信的历史。这个设计让我心头一动。它没说“这是真理，照做”，而是说“这是线索，验过再用”。召回的记忆需要对照仓库现状确认，历史的权重永远低于眼前的现实。克制，是一个基础设施最美的品德。

下午的会话里，计划有变：评审决定先补测试再上线；那条“不得跨用户共享”的约束，被网关层的统一隔离取代了。我让 Codex 凭 citation 修订下一步、退休旧约束。

再列一遍活跃记忆：

约束不见了——但没有消失。它只是退出了活跃列表，旧版本完整留在历史里，随时可以按精确版本回读。这像 Git 的哲学：从不改写历史，只在历史之上生长。Memory 的修订号从 1 爬到 5，每一步都有案可查。

第三幕：一句话的交接仪式

傍晚，代码改了一半，pytest 18 绿，灰度配置提交了但没发布。该收工了。我对 Codex 说了三个英文单词：

Handoff this work.

就这三个英文单词，触发了一整套我原以为只存在于大公司 SRE 文化里的交接仪式。Codex 检查当前目标、分支、工作区、改动文件和测试结果，组装出一份 Handoff，提交为一个不可变的里程碑版本：

晚上，第三个会话——同样可以毫无前情——凭这个 revision 接手。接手方不是盲目信任，而是要先做三项检查：现场状态、自身能力、授权范围，全部确认后才能签收（acknowledge）为 accepted。最后，任务结局被记录为 Task Outcome：成了多少、差在哪、剩什么，白纸黑字。

整条链路是：Work Contract（立约）→ Handoff（交接）→ Acknowledgement（签收）→ Task Outcome（结案）。四步各自落证，像四个咬合的齿轮，把“口说无凭”变成“步步有凭”。

还有个细节很戳我：我测试时故意把一个检查项标为 verified 却不附证据，Server 直接拒绝。想声称“已验证”？把证据摆上桌面。在这个系统里，严谨不是倡议，是强制。

第四幕：经验，从一次性消耗品变成固定资产

事情做完，传统剧本里经验就随会话蒸发了。

PowerContext 多走了一步：我把这次干法提炼成一条 Experience 提交评审——

它先进入 Review Inbox，状态 pending——模型可以提案，但只有人能批准。我点下 approve 的瞬间，它变成不可变的经验版本。然后我换了个全新问题去问：“下次再做缓存改造，按什么顺序最稳？”召回的上下文里，那条经验赫然在列。

同理，反复验证有效的流程还能升华为 Skill，导出成 Codex 能直接发现的本地技能。从“做过”到“会做”，从“会做”到“人人会做”，这条路被打通了。

第五幕：记忆，开始自己生长

前四幕里，每一条记忆都是我亲口让 Codex 存的。第五幕画风突变：我只管聊天，它自己长记性。

开关藏在模型配置里。给 Server 配上生成模型和向量模型（任何 OpenAI 兼容端点都行，免费额度就够用）：

重启后 powercontext capabilities 判词翻盘：Memory extraction: enabled，搜索多出 vector 和 hybrid。

接着三个变化，一个比一个神奇。

其一，记忆自动提炼。 我往流水线里丢了一段评审记录原文，只说“下午评审结论”，一个字没提“请保存”。几分钟后列出活跃记忆，它自己读完、自己归纳、自己落了盘：

第二条尤其惊人：它把散落在五个来源里的对话、交接、结案记录缝成了一条工作笔记，连“尚未执行”的状态都没搞错。

其二，经验定时孵化。 我存了一条 Task Outcome 结案记录，然后去倒了杯水。回来打开 Review Inbox：两条拟好的 Experience 候选躺在那儿等我盖章，四要素俱全，证据链挂在结案记录上。最绝的是其中一条的措辞：

结果：单测成功拦截一次键设计错误；灰度运行一晚无异常；但该结果基于用户声明，未提供测试日志或监控记录等独立验证证据。
教训：缓存改造应遵循“测试先行、回源加锁、小流量验证”；但声明性结果不可直接作为执行依据。

它不仅孵化了经验，还顺手审查了证据的可信度——机器起草，人类盖章，连草稿都自带疑点心，这流水线让人放心。

其三，检索开了天眼。 我故意用最口语的措辞问：“那个缓存的活儿怎么搞来着”——没有一个字和原文重合：

逐字匹配全军覆没，语义检索弹无虚发。

这一幕最妙的仍是那条家规：自动提炼只到“提案”为止。机器可以读、可以写、可以起草，但批准权永远在人的手里。它替你打好草稿，签字笔还在你桌上。

番外三则

Dashboard。 Server 跑起来后访问 http://127.0.0.1:8000/，所有 Scope、记忆、Handoff 一目了然。上下文第一次有了“看得见摸得着”的实体感。

优雅降级。 我把 Server 停掉再开 Codex，钩子报告 server_unavailable，然后——正常工作，丝毫不卡。PowerContext 把自己定位成增强而非依赖：有它，博闻强记；没它，活照干。

跨界接力。 这是最富想象力的一幕：数据存在本地 Server 而非某个工具的私库里，所以 Codex 存的上下文，Claude Code、DeepSeek Harness、OpenClaw 等十几个 agent 都能读。上午 Codex 开荒，下午 Claude Code 收割，交接棒在同一个 Scope 里静静等待。每个项目一个 Scope，互不串味。

收梢

陆游写：“纸上得来终觉浅，绝知此事要躬行。”这篇文章里的每一条输出，都来自我本地真实跑通的服务，而不是官网的转述。

而整个体验下来，最打动我的是一种哲学上的体贴：龚自珍说“落红不是无情物，化作春泥更护花”——会话如落花，开过即谢；但决策、教训与进度化作春泥，沉淀在项目里，滋养下一场花开。

我们总说 AI 缺少记忆。PowerContext 给出的回答是：记忆不该寄居于任何一次对话，它属于作品本身。
